What it does

Before it analyses anything, it opens everything.

Reads nested folders

Subfolders, archives, and workbooks with a dozen sheets are all walked in a single pass. Nothing gets skipped because it was one level down.

Counts what's there

Files, sheets, rows, columns, and total size — measured up front, so you know the scale of the job before anything loads into memory.

Flags what's broken

Merged header cells, shifting delimiters, empty sheets, files that failed to parse — listed with what Data Lens did about each one.

Spots duplicates

Files with identical or near-identical contents get grouped, so you don't analyse last quarter's export twice under two different names.

How it reads a folder

Four passes, all before you see a chart.

Directory analysis is deliberately cheap. Data Lens does the smallest amount of work needed to describe what's in front of it, then asks whether you want the full run.

01

Walk

Every path is enumerated and matched against supported formats. Unsupported files are listed rather than silently dropped, so you always know what wasn't read.

02

Peek

Only the first few hundred rows of each file are read to infer structure. A 400 MB workbook costs the same at this stage as a 4 KB one.

03

Check

Headers, delimiters, encodings, and sheet contents are validated. Anything ambiguous is repaired where it's safe to, and reported where it isn't.

04

Fingerprint

Each file gets a content hash and a column signature, which is how near-duplicates and renamed exports are grouped together.
