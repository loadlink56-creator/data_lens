What it does

It reads the values, not the column name.

Real type inference

Text, number, date, boolean, or category — decided by sampling the actual values, with a confidence score you can see and override.

Key detection

Unique and near-unique columns are surfaced as candidate primary keys, with null counts and duplicate examples attached.

Naming variants

cust_id, CustomerID, and cust id get recognised as the same field, so joins don't fail on formatting.

Schema drift

When the same column has a different type or format in a different file, you find out here — not three steps later when a chart looks wrong.

Why it matters

Most bad analysis starts with a mistyped column.

A date read as text won't sort. A number read as text won't average. An ID with hidden duplicates will quietly multiply your row counts on the first join. Schema analysis is the cheapest place to catch all three.

01

Sample, then confirm

Types are inferred from a stratified sample, then verified against the full column. A single stray value doesn't get to decide the type — but it does get reported.

02

Formats, not just types

Dates, currencies, percentages, and thousands separators are normalised, so "₹1,20,000" and 120000 end up as the same number.

03

Cardinality matters

A number column with eight distinct values is probably a category. Data Lens says so, and treats it accordingly in every chart downstream.

04

You get the final say

Every inference is editable. Change a type once and the profiles, charts, and tests that depend on it all recompute.
